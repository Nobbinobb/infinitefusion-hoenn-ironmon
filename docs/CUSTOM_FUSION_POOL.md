# Custom-sprite fusion pool

Ironmon builds one candidate pool from the custom sprite index that Infinite
Fusion loads from `Data/sprites/CUSTOM_SPRITES` during startup. Alternate
sprites are already grouped under one fusion key by that index.

## Validation

Each candidate must:

- use the engine's `B<body>H<head>` fusion identifier;
- have at least one `main` or `temp` sprite in `Sprite_Credits.csv`, matching
  the variants the normal battle renderer is allowed to select;
- have valid body and head IDs in the active base-species range;
- resolve to a normal two-species fusion dex number;
- remain below the game's triple/special fusion range.

Normal species, autogenerated sprites, alternate-only entries, malformed keys,
invalid component IDs, and triple/special fusions are therefore excluded.
Invalid entries are skipped. An unavailable, empty, or entirely invalid source
produces a clear error before Ironmon run generation begins.

The final pool is kept even-sized so every admitted fusion has a distinct
Ironmon reverse partner. If filtering leaves an odd count, one deterministic
tail entry is excluded.

## Caching and reproducibility

Accepted species are sorted by fusion dex number and frozen. The service builds
the pool once per game process and returns the cached array afterward.

Every generated run records the pool schema version, candidate count, and a
deterministic FNV-1a fingerprint in save metadata. These values identify the
exact ordered candidate set used for generation without storing the full pool
in every save.
