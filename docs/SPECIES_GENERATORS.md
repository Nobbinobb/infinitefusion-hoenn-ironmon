# Wild and trainer species generators

Step 1.5 replaces Ironmon's direct dependence on the base game's shared
species mapping with two seed-derived generators. Wild encounters, starters,
gifts, and scripted or static encounters use the wild generator. Trainer party
slots and resolved trainer placeholders use the trainer generator.
The legacy rival placeholder is derived directly from the trainer generator.
Hoenn's rival, Wally, and rematch system keep story-owned teams that can catch,
fuse, unfuse, reverse, and evolve Pokémon. Ironmon leaves those story teams
intact and maps cloned parties through the trainer generator immediately before
custom or rematch battles. This prevents dynamic story changes from bypassing
the configured trainer policy.

Hoenn's rival retains a normal internal starter source because later scripts
fuse that starter with another species. The player only battles the
trainer-policy mapping of that source or resulting story fusion, so the code
never attempts to create a fusion of an already-fused randomized result.

## NPC story fusions

Story events may try to fuse Pokémon which the active wild policy has already
made into fusions. The shared NPC helper reduces the intended body input to its
base body component and the intended head input to its base head component. It
then creates one valid two-base source fusion. This rule is used by Wally and
trainer-rematch fusion events and is available for other NPC scripts discovered
later.

Wally's standard gift event allows fused Pokémon to be selected but normally
rejects them afterward. Ironmon redirects that one check so he accepts fused
gifts while Ironmon is active. Other modes retain the original behavior. His
fusion preview uses the flattened base inputs, and his eventual battle party is
still projected through the configured trainer policy.

## Determinism

Each result is derived from the generator schema version, run seed, generator
namespace, source species, and selection purpose. It does not depend on call
order. The generated maps are stored in `PokemonGlobalMetadata` and survive
save/load. F7 creates a new seed and completely replaces both maps.

Wild and trainer namespaces are deliberately different, so their mappings are
independent even when both use the same policy.

## Policies

- `Normal Only` selects from the 576 validated base species.
- `Custom Fusions Only` selects from the validated Step 1.4 custom-fusion pool.
- `Mixed` makes a deterministic 50/50 normal-versus-fusion category decision
  before selecting a species from that category's pool.

Autogenerated, malformed, invalid, and special fusion entries cannot enter the
custom-fusion pool. Missing local sprite images remain eligible because the
base game can download their spritesheets on demand.

Visible overworld encounters use the same wild generator as grass encounters.
Both fixed and dynamically spawned overworld events are mapped in their shared
setup class so the visible sprite agrees with the eventual battle. Their
Pokemon objects carry an in-memory marker that prevents the specific-Pokemon
battle entry point from mapping them twice. A new fusion constructed by the
overworld group-battle system has no marker and is therefore projected through
the wild policy before battle.

## Compatibility

Step 1.4 and earlier saves retain their existing base-game mappings when loaded.
Their first F7 reset generates the new schema-version-1 wild and trainer maps.
Loading a Step 1.5 save clears only the in-memory generator objects and reconnects
them to the mappings stored in that save.
